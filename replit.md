# CyberDeck Radio

A static radio-discovery app for finding real stations worldwide, presented as a **full-screen atlas**: a pannable world signal map (cluster bubbles + pips over a ~38k-channel catalog) with a now-playing dossier floating over it. The directory is a slide-over drawer opened on demand — header count button, search, or source switch — never on cold load. Picking a channel (a pip, a row, or the hop arrows) tunes and plays it at once; the map's pan-to-tune gesture only locks a station, so scanning stays quiet.

## Run & Operate

- `pnpm --filter @workspace/cyberdeck-radio run dev` — run the web app through its managed workflow
- `pnpm --filter @workspace/cyberdeck-radio run typecheck` — typecheck the web app
- `pnpm --filter @workspace/cyberdeck-radio test` — run station-provider tests
- `pnpm --filter @workspace/scripts run scrape:radio-garden` — crawl radio.garden into `public/radio-garden.json` (env: `RG_PLACES_LIMIT`, `RG_CONCURRENCY`, `RG_RESOLVE_STREAMS`)
- `pnpm --filter @workspace/api-server run dev` — run the API server (port 5000)
- `pnpm run typecheck` — full typecheck across all packages
- `pnpm run build` — typecheck + build all packages
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from the OpenAPI spec
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)
- Required env: `DATABASE_URL` — Postgres connection string

## Stack

- pnpm workspaces, Node.js 24, TypeScript 5.9
- API: Express 5
- DB: PostgreSQL + Drizzle ORM
- Validation: Zod (`zod/v4`), `drizzle-zod`
- API codegen: Orval (from OpenAPI spec)
- Build: esbuild (CJS bundle)

## Architecture decisions

- CyberDeck Radio is a static, browser-only app. It opens on the RADIO GARDEN source — a ~38k-channel catalog baked at build time from radio.garden and shipped as `public/radio-garden.json(.gz)` — and can still switch to the live Radio Browser (AIRWAVES) or SomaFM sources on demand.
- The app is atlas-first: the world map owns the full canvas and the now-playing dossier floats over it. The directory is a slide-over drawer (right rail on wide screens, bottom sheet with a grabber handle on touch) that is opened deliberately — the header channel-count button, a submitted search, or a source switch — never on cold load, so the map keeps the first paint. While open it traps focus, scroll-locks the page, and closes on Escape (returning focus to its toggle); a search that lands results slides it open, and a deliberate pick scrolls its row into view.
- The map keeps its atlas behavior end to end: animated pips, nearest-center tuning on pan-settle, and a fly-to only for deliberate picks (row, pip, hop) so exploring never snaps back under the cursor. Pips are disabled under `prefers-reduced-motion`.
- Stations with coordinates emit an animated pulse; pulling the map (pan/zoom) tunes the nearest signal once the gesture settles, and selecting a station deliberately (row, pip, hop) flies the map to it. An automatic nearest-lock never re-zooms under the cursor.
- The interface ships a set of runtime themes, each a full transformation rather than a re-colour: "Signal" (the amber-on-slate default), four elements (Water, Air, Fire, Earth), two cartoon skins (Bubblegum, Comic), two Japan-inspired (Sakura, Matsuri), two China-inspired (Lantern, Jade), and four India-state-inspired (Rajasthan, Kerala, Punjab, Tamil). A skin is now a pair of `[data-theme="…"]` token blocks in `index.css` — the colour block **plus** a structural block (a `:root` default overridden per family) carrying **type** (`--font-brand`/`--font-display`/`--brand-tracking` over curated display faces — Baloo 2 for Cartoon, Shippori Mincho for Japan, Noto Serif SC for China, Rozha One for India, with Cinzel remaining the Signal/elemental titling face — loaded as new families on the Google Fonts `<link>` in `index.html` and re-declared by the CSS `@import` at the top of `index.css`), **geometry** (`--panel-radius`, `--btn-radius`, and the `--radius-*` shape language: square for Comic/Tamil, round for Bubblegum/Air/Jade/Kerala, arched for Rajasthan), **motion** (`--dur-fast`/`--dur-base`/`--dur-slow`, `--ease-standard`/`--ease-emphasis`, and `--motion-scale`, which lets the toons bounce while the elements and cultural skins drift), and **material** (`--grain`, a tiled fractal-noise overlay, and `--sheen`, a lacquer highlight, plus per-family component chrome: inked cartoon outlines, China lacquer frames, a Japan paper hairline, an India selvedge stripe, and a glow on the elemental primary transport). Alongside them sits a `ThemeDefinition` in `themes.ts` that names a station-pin glyph (`PipShape`), a tiled decorative backdrop (`BackdropArt`), a shader temperament, and a `SoundProfile` — the skin's interface voice, kept in the `THEME_SOUNDS` table and joined in by `getThemeDefinition`, which `audio/ui-sound.ts` synthesizes into per-skin WebAudio cues with no audio files, voiced by `use-theme-cues.ts` on control taps and skin changes and gated by the mode dock's Sound toggle (`soundCues`, persisted, default on). The `ThemeSwitcher` in the mode dock previews each skin on its own tokens and swaps them, the choice persists in preferences, and the `<html data-theme>` attribute is the single switchboard for the whole skin. Station pips repaint from `currentColor` (so health/selected/pinned colouring is unchanged) while their glyph and ambient motion follow the motif, and the decorative SVG layer tints from `--accent`. Those same tokens feed the WebGL backdrop: `ShaderBackdrop` (`components/atlas/ShaderBackdrop.tsx`) re-reads `--bg`/`--bg-subtle`/`--card`/`--accent` when the theme changes and picks that theme's `distortion`/`swirl`/`speed`/`grain` uniforms for a Paper Shaders `MeshGradient` canvas layered under the SVG world (z-index 0; the world sits at 1). The backdrop is atmospheric only — capped at ~1.1M pixels and pixel-ratio 1, frozen to a static frame under `prefers-reduced-motion`, wrapped in the app `ErrorBoundary` with a silent fallback, and skipped entirely when WebGL2 is unavailable.
- Two view modes sit on top of the atlas, both driven by classes on `.app`. **Zen** (`is-zen`) drops the header, footer, and ruler so the world, the dossier, and the mode dock are all that's left; Escape (or the dock) puts the chrome back. **Screen saver** (`is-screensaver`) engages after 60 s of stillness or on demand, hides every control but leaves the world as a live backdrop, and shows a centered station identity (name, synthetic carrier, level meter, status, UTC clock) over a dimmed canvas. Waking is deliberate — `pointerdown`/`keydown`/`wheel`/`touchstart` only, never pointer drift — so the saver can sit ambiently; controls marked `data-screensaver-control` (its own play/pause) never wake it, so playback can be steered from across the room. Auto-engagement is gated off while the directory drawer is open, waking never is, and neither mode is persisted — each session starts with the full atlas.
- Keep provider JSON behind the station adapter; UI code consumes only the app-owned `Station` type.
- The world is hand-rolled SVG over the bundled Natural Earth boundaries — no tile server, API key, or map library; WebGL exists only as the decorative `ShaderBackdrop` mesh gradient behind it (Paper Shaders, zero-config canvas, gracefully absent without WebGL2). Markers are world-space `<g>` elements scaled by `1/fit` against a 1000×500 sheet, so geometry is authored in pixels and survives any viewport shape.
- The template's unused providers (react-query `QueryClientProvider`, `TooltipProvider`, `Toaster`) were removed from the app shell — nothing in the app uses query hooks, tooltips, or toasts.
- The map selects the station closest to its center after search results load or map movement settles; focus changes do not start playback.
- Channels are surfaced through a source registry (`sources.ts`); each source advertises hint/placeholder copy, whether it is geotagged (can pin the atlas), and how to list/search. AIRWAVES searches/traffic-sorts Radio Browser; SOMA FM caches `channels.json` and filters client-side; RADIO GARDEN serves a pre-scraped catalog and filters client-side.
- Radio Garden's JSON API is CORS-locked to its own origin and gated by Cloudflare, so the browser cannot call it. A scheduled GitHub Action crawls it in Node (browser User-Agent, no CORS) and bakes `public/radio-garden.json` before the Pages build. The crawler collects every place in two bulk requests (`places-core-columnar` + `places-details-columnar`, the same endpoints the official client merges by index) and saves each channel's stable HTTPS `channel.mp3` listen URL as its stream, so it does not resolve ~38k redirects (that is opt-in via `RG_RESOLVE_STREAMS=1`); a full crawl takes under a minute locally. The catalog is gitignored and cached per-day in CI so ordinary pushes skip the crawl.
- The atlas opens on the whole baked catalog — no trending fetch, no row cap. Browse and search return every station (~38k); the map clusters them under a marker budget and the directory pages 60 rows at a time behind a "Show next N channels" button, so the DOM never carries the full catalog. AIRWAVES still opens on its trending pool when the user switches to it, and non-geotagged catalogs (SomaFM) never pin the map, showing a "no usable coordinates" empty state instead.
- One marker pass (`buildStationMarkers` in `station-markers.ts`) carries the whole catalog: stations are projected onto the 1000×500 sheet, off-viewport ones are culled against a padded viewport at the current zoom, and the rest are merged by a world-space grid that grows its cell until the count fits a 640-marker budget. A dense city reads as a cluster bubble — `Zoom to N channels` — with a hover hint naming the count, the dominant country, and whether the tap expands or chooses; the locked station is always emitted last as its own pip. A deep dive on a bubble finds the zoom where its channels stop sharing cells (bisected from the same grid, then verified against a real marker rebuild so the budget cannot lie) and flies there, while a crowd no zoom can split — co-located city channels — opens the anchored `ClusterPicker` dropdown instead; any camera move retires an open picker so it can never outlive its bubble.
- The directory is paginated at 60 rows a page (`DIRECTORY_PAGE_SIZE`); the search still keeps the full match set for facets, counts, and hopping while the DOM stays small. A deliberate pick that is off-page expands `listLimit` to its page and scrolls the row into view. The dossier's hop arrows (←/→) walk the current result pool in order and tune each stop with autoplay, so a channel binge never needs the drawer open.
- Channel keeping is shelf-based: a pin (row button, dossier pin, or the `P` shortcut) stores a whole channel snapshot in localStorage (`pinned-channels.ts`) so it stays tunable across reloads and source switches; the drawer's shelf switcher swaps the live directory for the pinned shelf or the recent-channels dial log, and pinned map pips wear a kept-channel ring. Recents only record channels that actually started playing, so the log is a listen history, not a click trail.
- A background Worker ("stream health") marks any station with no HTTPS stream `insecure` immediately (no probe spent on it) and probes every remaining station's `checkUrl` off the UI thread, reporting live/offline/checking/unknown. Insecure and non-HTTPS stations are pruned from the directory and map, so the deck never surfaces "No secure stream is available". Records carry the live/offline state via green/red dots in the directory, colored + haloed (and pulse-excluding) map pins, an offline icon in each list row, and a health chip on the deck.
- Offline is a two-strike verdict: one failed probe only holds the previous status and schedules a quick confirming probe (~45 s); a second consecutive failure reports the channel offline, which quarantines it into a localStorage blob (`stream-quarantine.ts`, same total-parse pattern as preferences) and removes it from the directory, map, facets, and hop pool. The worker keeps quarantined channels registered and re-probes each on a randomized 10–20 minute cadence; the first live verdict restores the record automatically. Tuning a station that turns insecure or confirmed-offline clears the dossier and stops playback, mirroring the insecure prune. Quarantine survives reloads, so dead channels stay hidden until re-verified; a fresh search that re-surfaces a quarantined id triggers an immediate re-verify instead of waiting out the recovery window.
- Radio Browser probes reuse its server-side stream validation via `GET /json/url/{uuid}` (CORS-safelisted); SomaFM probes the lightweight `https://somafm.com/{id}.pls` playlist because icecast returns 403 to browser fetches. The probe never reads a stream body: it classifies first, then cancels the response body so API JSON is still readable.
- The directory is Apple-Watch-dense: rows show an index, health dot, and name at rest; country/genres/codec expand on hover/focus/selection. Touch and `(hover: none)` environments always show the details. Result changes are mirrored into an off-screen `role="status"` region so screen readers hear the count.
- Search is faceted and composite. The header field is a combobox: focusing it (or pressing `⌘K`/`Ctrl-K`, or `/` when nothing else is typing) opens a suggestion palette — remembered scans, then stations (name-prefix ranked), countries, cities, and genres from the loaded catalog (debounced 150 ms over a per-array lower-cased haystack cache), plus a "Scan “…”" row; ↑↓/Enter walk it, a station option tunes at once, and a term option fills the field and runs the same scan, which is also what gets remembered (localStorage, max 6). The scan itself hits the provider — Radio Browser queries name/tag/country/state in parallel (a wider pool than before: 60 per field, 250 trending) while the garden and SomaFM catalogs filter client-side through a normalized, diacritic-blind, token-AND match over name, country, region, city, genres, and homepage — and the directory then refines those results instantly, client-side, through cascading facets (country → region → city, genre, codec) plus a sort (featured, name A–Z, country, bitrate). Each facet's option list is derived from the stations matching all the *other* active facets, so picking a country narrows the region/city lists without collapsing the country list; a facet hides a station only when that station is missing the metadata the facet reads. City comes from the Radio Garden crawl (each channel inherits its place title); Radio Browser supplies `state`. The palette's suggestions are a fast substring index, not a second matcher — the directory scan stays the diacritic-blind source of truth.
- The header's "Surprise me" control tunes a random station from the current, filter-applied result pool (falling back to the unfiltered one), skips whatever is already locked so repeated presses keep moving, and re-opens the directory so the pick is visible; it is disabled while nothing is loaded. The choice is a pure function (`pickRandomStation`) with an injectable RNG.
- One `AudioController` owns one audio element and is the single source of playback truth; the deck renders controller state and never guesses from button clicks. Clicking a channel (list row or map marker) locks it and starts playback immediately; the map's pan-to-tune gesture only locks the nearest station. Switching stations mid-playback emits a `loading` state flagged `switching`, so the deck shows a graceful `SWITCHING` transition instead of a plain `TUNING` flash.
- Stream candidates are filtered to HTTPS on an HTTPS page and tried in order with at most one pass; a rejected `play()` (autoplay policy) is a recoverable error, not a silent success. Radio Browser search/trending request `is_https=true`, and normalization prefers an HTTPS URL across `url`/`url_resolved`, dropping any record with no HTTPS candidate.
- Playback state and the tuned station are mirrored to the Media Session API (when available) so lock-screen / hardware media keys control the same single `AudioController`; the integration no-ops where the API is missing.
- The spectrum taps the real audio via `HTMLMediaElement.captureStream()` → `AudioContext` → `AnalyserNode`, created once on the first confirmed `playing` event. `captureStream()` only taps the element's output, so an unreadable (CORS) stream still plays normally; the deck detects a flat signal and honestly reverts the label to `SIMULATED`. If the browser lacks the APIs, it stays simulated.
- The hero derives a stable per-station accent hue (hashed from the station id, defaulting to the brand green) that tints the deck art glow, its border, and the visualizer spectra, so each tuned channel reads as its own "record". With no station locked the art shows an empty-state placeholder (and hides the visualizer label/style controls) instead of a dead canvas.
- Volume, visualizer style (spectrum or VU), the active theme, and the interface-sound toggle (`soundCues`, default on) are persisted in one small localStorage blob; the analyser tap is built lazily and torn down with the controller. Interface cues are a cosmetic layer only — the WebAudio engine is a silent no-op without Web Audio, so it never breaks the interaction it decorates.
- Do not proxy or downgrade stream URLs, and never re-route audio through a `MediaElementSource` (it silences cross-origin streams). Playback work must preserve HTTPS-first behavior and continue direct audio if Web Audio processing is blocked.
- Do not add a runtime backend, database, account system, or AI model. The one sanctioned crawler is the Radio Garden scraper, which runs only at build time in CI and emits a static file — the app stays browser-only and same-origin.

## Product

Listeners land on a world map already lit with the full ~38k-channel Radio Garden catalog — co-located channels merged into cluster bubbles that a deep dive either splits apart on the map or hands to a channel dropdown when they are too stacked to separate — and search from the header field, whose palette offers remembered scans, matching stations, countries, cities, and genres as they type (or switch to the live AIRWAVES/Radio Browser directory or the SomaFM lineup). Matching stations refill the map, and the directory slides open as a drawer with 60 rows a page for drill-in through cascading facets (country → region → city, genre, codec) and a sort; **Surprise me** locks a random channel from whatever the filters currently allow, and the dossier's hop arrows walk the result pool without opening the drawer. Picking a channel (a map pip, a directory row, a palette suggestion, a picker row, or a hop) loads it into the floating dossier (audio-synced visualizer, identity, health, codec) and starts it over its HTTPS stream with play/pause/stop and volume controls; switching stations shows a graceful `SWITCHING` transition, and panning the map tunes the nearest signal without kicking off playback. Stations with no HTTPS stream are pruned in the background so the player never offers an unplayable channel; failed streams surface an explicit error and can be retried without reloading. A mode dock on the canvas offers a calmer listen (zen: header, footer, and ruler hidden) and a screen saver — either launched by hand or automatic after a minute of stillness — that dims the atlas to an ambient station read-out until any deliberate input wakes it.

## User preferences

- Interface direction: full-screen atlas (world map owns the canvas, dossier floats over it), a runtime theme switcher in the mode dock (15 skins — Signal, the four elements Water/Air/Fire/Earth, Cartoon Bubblegum/Comic, Japan Sakura/Matsuri, China Lantern/Jade, and India Rajasthan/Kerala/Punjab/Tamil — each a full skin: palette, station-pin glyph, decorative SVG backdrop, ambient motion, structural tokens for type/geometry/motion/material in `index.css`, and an interface sound voice synthesized as WebAudio cues that the dock's Sound toggle can mute), and the whole catalog on the map with a drawer directory for drill-in. No Winamp/JetAudio audio-component skinning — the skins restyle the atlas, the pips, and the interface voice, not the player chrome.

## Gotchas

- Radio Browser records can omit country, state, genres, coordinates, bitrate, or resolved stream URLs; treat those fields as optional. Only Radio Garden records carry `city` (the crawled place title), and only Radio Browser records usually carry `state` — a facet list is only as complete as the catalog behind it.
- Stations without valid coordinates remain searchable but cannot appear on the map or be selected as the map-center nearest station.
- A directory result is not a guarantee that a stream is currently reachable. Keep provider errors distinct from a successful search with no results.
- Marker geometry is authored in pixels against the 1000×500 sheet and scaled by `1/fit`; never write SVG-unit constants for pin radii, hit targets, or cluster bubbles or they will drift on non-2:1 viewports.
- Every channel of a Radio Garden city shares the place's single coordinate, so no zoom can separate that crowd — deep dives detect it up front (`findSeparationScale` returns null) and open the channel dropdown instead of flying. Never "fix" this by faking offsets on identical points; the picker is the honest answer.
- The catalog is far larger than any DOM budget: never map all ~38k stations into rows or markers. The directory pages 60 rows at a time and the map clusters under a 640-marker budget, while counts, facets, search, and hopping all keep the full result set in memory.
- Vite emits workers as IIFE by default; module workers must set `worker: { format: 'es' }` in `vite.config.ts` or `new Worker(..., { type: "module" })` fails to parse.
- Never cancel `response.body` before reading a JSON health probe — it consumes the body and turns valid `{ok:true}` responses into "offline". Classify first, cancel after.
- icecast-style mounts (e.g. `ice2.somafm.com/…-128-mp3`) can return 403 to browser `fetch`; probe reachability with the channel's `.pls` playlist URL instead.
- radio.garden returns a Cloudflare `403` challenge to plain requests and only sets `Access-Control-Allow-Origin` for its own origin; the crawler must send a browser User-Agent (and never runs in the browser). The generated `public/radio-garden.json` is gitignored, so the adapter treats a missing file (`404`) as an empty catalog rather than an error — the RADIO GARDEN source is simply empty until CI bakes it.
- Radio Garden API paths keep the `/ara/content/` prefix (`/ara/content/places`, `/ara/content/page/{id}/channels`, `/ara/content/listen/{id}/channel.mp3`); the unprefixed shapes (`/page/{id}/channels`, `/listen/…`) return `404`. The `places-core-columnar` endpoint is 4× smaller but only carries `ids/lngs/lats/sizes/boosts` — no titles or countries — so it cannot replace `/ara/content/places`. Verified against the live API 2026-10-10.
- The Radio Garden catalog is ~10 MB, so the deploy workflow also publishes `public/radio-garden.json.gz`; the adapter fetches the gzip copy and decompresses via `DecompressionStream`, transparently falling back to the plain JSON file when it is missing, undecodable, or `DecompressionStream` is unavailable.
- An HTTPS page cannot play `http:` media, so a station is only usable when it has at least one `https:` stream. Rather than showing "No secure stream is available", such records are dropped at normalization and re-checked off the UI thread by the worker, which reports them `insecure` and the app prunes them from the directory and map.
- `captureStream()` on a cross-origin media element can yield a silent (muted) tap; that is expected and safe — the element's own playback is untouched. Detect the flat signal with `analyserHasSignal` and keep the visualizer labeled `SIMULATED` so it never fakes analysis.
- The deploy workflow caches the scraped catalog per day (`actions/cache`), falls back to the newest cached copy through `restore-keys` when the crawl fails, gzips it for the wire, and **fails the deploy outright when no catalog exists at all** — a node check that also warns past a fortnight of staleness. `workflow_dispatch` takes a `force_scrape` input to re-crawl despite a cache hit, and every run archives the shipped `radio-garden.json(.gz)` as an artifact so a regression can be diffed against what went live. The daily cron stays at `23 4 * * *`.
- Follow radio.garden's `channel.mp3` redirect with `redirect: "manual"` and read the `Location` header; the resolved direct URL is only kept when it is `https` (the app's HTTPS-only playback rule), with the `https` `channel.mp3` listen URL retained as a playable fallback. Resolving is opt-in (`RG_RESOLVE_STREAMS=1`) because a full crawl would otherwise follow ~38k redirects; CI leaves it off.
- The app's Vite workflow supplies `PORT` and `BASE_PATH`; do not start the artifact with a manually configured duplicate workflow.
